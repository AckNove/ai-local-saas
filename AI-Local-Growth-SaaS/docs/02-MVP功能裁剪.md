## 0. MVP 决策原则（裁剪总纲）

围绕"最低成本、最快验证商业闭环"的目标，本报告的裁剪遵循三条铁律：

1. **主链路优先**：凡是支撑「管理员创建商家 → 生成种草卡 → 消费者扫码跳转 → 记录数据 → AI 生成内容」这条技术闭环的功能，一律纳入 MVP（P0）。
2. **销售辅助可后置**：帮助"找到更多商家 / 规模化销售"的能力（雷达、CRM、代理、自动销售），在尚无成功案例前一律暂缓——与个人销售验证无关。
3. **依赖外部即裁剪**：凡依赖 NFC 物理硬件、微信深度接口（自动发布/读取视频号互动）、支付系统、微信小程序的能力，7 天验证期内裁剪或暂缓，仅保留数据模型预留。

> 一句话：**MVP 只做"能让 1 家真实商家跑通扫码→点击→互动闭环"的最小功能集。**

## 0.5 产品边界声明与架构决策确认（吸收技术评审 D2/D3/D4，反馈 D1）

> 本节为产品经理对架构师《技术评审报告》（docs/01-技术评审.md）决策点 D1–D4 的产品侧回应，需写入代码规范与验收口径。

### 0.5.1 产品边界声明（三条，必须写进代码规范与验收）

1. **NFC 边界（对应 D2）**：NFC 仅保留数据模型（`seed_card.type` / `nfc_id`）与读卡接口预留；主路径一律走二维码（segno 生成）。**NFC 真机写卡 / 读取不属于 MVP 验收点**，写卡由外部工具 / 手机 NFC 完成，延后验证。
2. **微信 / AI 发布边界（对应 D3）**：AI 内容模块（F 视频脚本、评论、活动方案；D AI 视频优化建议）定位为"生成草稿 + 优化建议"，由商家手动发布到视频号。**MVP 范围严禁出现"自动发布到视频号"**；AI 视频优化 = 建议文本而非执行动作。
3. **agent 角色边界（对应 D4）**：RBAC 预留 `admin` / `merchant` / `agent` 枚举与鉴权钩子，但 agent 具体逻辑（代理看板、分成）放到 V2。**MVP 功能列表里 agent 相关项标注"预留 / 不实现"**。

### 0.5.2 产品对架构决策的确认

- **D1 反馈（SQLite 默认 vs 强制本地 PG）**：**产品侧同意采纳"默认 SQLite + `DATABASE_URL` 可切 PG"**。理由：MVP 第一目标是零摩擦本地一键运行 + 无 API Key 即可完整 Demo（地推 / 拜访商家时任何笔记本都能当场演示），且 MVP 并发极低（单人运营、少量商家），SQLite 完全够用；生产经 `DATABASE_URL` 一键切 PG 即可满足 PRD 多租户 / V2 扩展意图，不牺牲原意。**配套约束**：MVP 不使用 PG 专有类型（JSONB / ARRAY / UUID），统一 SQLAlchemy 通用类型，保证方言无关、未来含 `seed_event` / `ai_task` 等只追加表可平滑迁移。
- **D2 / D3 / D4**：产品侧确认同意，按 §0.5.1 边界推进。

### 0.5.3 离线可运行确认（P0 安全）

架构师指出：P0 必须项（用户系统、商家管理、AI 诊断、种草卡生成、二维码生成、AI 评论生成、基础数据统计）在"SQLite 默认 + AI Mock Provider 兜底"选型下均可**离线、无 API Key 完整跑通**。报告确认：MVP 范围可放心保留这些 P0 项，验收不以真实 LLM 为前提。

## 2. 核心功能 vs 次要功能区分

### 2.1 不可替代核心（支撑"商业闭环验证"主链路）

以下链路任一环节缺失，则无法在 7 天内验证「商家愿付费」这一终极目标，故全部纳入 MVP：

```
管理员登录(0)
  → 创建商家(A.2) + 填视频号链接(D.1/C.2部分)
  → 生成种草卡(E.1) + 配置跳转目标(E.2视频号/自定义) + 生成二维码(E.4)
  → 消费者扫码落地页(I) 记录 scan/click
  → 跳转视频号/自定义页(主链路跳转)
  → 基础数据统计(G.1 / A.1.1 / A.1.2)
  → AI 生成评论(F.2) + AI 生成内容/脚本草稿(F.1)
```

**技术闭环核心（10 项，缺一不可）**：
1. 用户系统—管理员登录（0）
2. 商家管理—创建+信息管理（A.2，含视频号链接 D.1）
3. 种草卡创建（E.1）
4. 跳转目标管理—视频号/自定义（E.2 部分）
5. 二维码生成与下载（E.4，segno 生成）
6. 消费者扫码 H5 落地页 + 访问记录（I，scan/click 写入 seed_event）
7. 基础数据统计—种草卡生成/扫码/点击（G.1、A.1.1、A.1.2）
8. AI 评论生成（F.2）
9. AI 视频脚本/内容生成（F.1，输出草稿由商家手动发布）
10. 视频绑定（D.2 部分，种草卡绑定视频）

> 注：B.2 **AI 商家诊断**虽列为 P0，但它服务于"免费诊断→成交"的**商业验证（销售 Demo）**，不属于上述"技术闭环"主链路，但因其被 PRD 明确列入 P0 且直接支撑成交，仍纳入 MVP，归类为"商业验证支撑型 P0"。

### 2.2 可后置次要功能（验证期非必需）

- **规模化获客类**：AI 商家雷达(B.1)、CRM 线索(H.1)、跟进记录(H.2)、自动化销售 Agent —— 个人销售阶段用手工即可。
- **商家自助类**：商家后台首页(C.1)、商家自助门店编辑/Logo(C.2 全量)、服务套餐(C.3) —— MVP 由管理员代运营。
- **深度内容与分析类（均输出草稿/建议，不自动发布）**：AI 视频优化建议(D.3)、AI 活动方案(F.3)、视频互动数据(G.2)、增长周报(G.3) —— 依赖微信接口或历史数据，验证期数据不足。
- **硬件/生态类**：NFC 管理(E.3，仅数据模型+读卡预留，写卡延后)、小程序跳转(E.2 类型2)、微信深度接口(自动发布受限)、支付系统(A.1.3 收入) —— 依赖硬件或 P2 生态能力。
- **平台化类**：代理体系（agent 角色仅预留枚举与鉴权钩子，具体逻辑 V2 不实现，D4） —— 无成功案例前无法复制（PRD-06 §6）。

**数据表落地汇总（MVP 必建 7 张）**：`sys_user`、`merchant_info`、`store_info`、`seed_card`、`seed_event`、`video_content`、`ai_task`（全部来自 PRD-04 §5，无需新增表结构）。

**角色与扩展预留（D4）**：`sys_user.role` 保留 `admin` / `merchant` / `agent` 枚举与鉴权钩子，`agent` 具体业务逻辑（代理看板、分成）V2 不实现；`seed_card.type` 预留 `nfc` / `qr` 以支持 NFC 数据模型（写卡延后，D2）。

**接口补全建议（PRD-04 未覆盖但 MVP 需要）**：
- `GET /api/seed-card/{id}/qrcode` —— 二维码图片获取/下载（segno 生成）
- `POST /api/ai/content` —— AI 视频脚本/文案生成（与诊断报告 `/api/ai/report` 区分）
- `GET /api/stats/overview` —— 平台基础统计（种草卡生成/扫码/点击/AI 次数）
- `GET /api/stats/seed-card` 或 `/api/seed-card/{id}/stats` —— 单卡数据统计

## 4. 裁剪功能列表 + 理由

以下为被暂缓/裁剪的功能，每条附一句理由（含架构师技术评审 D2/D3/D4 边界）：

| 功能 | 原优先级 | 处置 | 裁剪理由 |
|---|---|---|---|
| AI 商家雷达（B.1） | P1 | 暂缓 | 依赖地图/公开数据采集与外部数据，7 天 MVP 非必需，销售可手动筛选 |
| 商家后台首页（C.1） | P1 | 暂缓 | 属商家自助后台，MVP 由管理员代运营，商家自登录非必需 |
| 商家自助门店编辑/Logo/图片（C.2 全量） | P1 | 暂缓 | 商家自助登录未开放，视频号链接已由管理员代填 |
| 服务套餐管理（C.3） | P1 | 暂缓 | 套餐为线下签约手动记录，系统内套餐管理非验证必需 |
| AI 视频优化建议（D.3） | P1 | 暂缓 | 输出优化建议文本而非执行动作（D3）；依赖视频号数据接入 |
| NFC 管理（E.3） | P1 | 暂缓（仅数据模型+读卡预留） | 依赖 NFC 物理硬件写卡，主路径走二维码(segno)；真机写卡/读取延后，非 MVP 验收点（D2） |
| 小程序跳转目标（E.2 类型2） | — | 暂缓 | MVP 不开发微信小程序（PRD-04 §3.3），小程序跳转目标不可用 |
| AI 活动方案（F.3） | P1 | 暂缓 | 输出活动方案草稿由商家手动执行（D3）；非 7 天验证必需 |
| 视频互动数据（G.2） | P1 | 暂缓 | 需微信接口读取视频号互动（P2），MVP 仅记录自有种草卡事件 |
| 商家增长周报（G.3） | P2 | 暂缓 | 属 AI 增长分析 Agent(P2)，需历史数据积累，验证期数据不足 |
| CRM 线索管理（H.1） | P1/P2 | 暂缓 | MVP 单人手动销售，线索管线非必需（PRD-04 列为第二阶段） |
| 跟进记录（H.2） | P1/P2 | 暂缓 | 随 CRM 一并暂缓 |
| Dashboard 收入数据（A.1.3） | P2 | 暂缓 | 依赖支付系统(P2)，MVP 收入手动记录，不纳入基础统计 |
| 代理体系（含 agent 看板/分成） | P2 | 裁剪（角色枚举预留） | V2 再开放；`sys_user.role` 的 agent 枚举与鉴权钩子预留，具体逻辑不实现（D4） |
| 自动化销售 Agent | P2 | 裁剪 | 依赖雷达/诊断/CRM 成熟，MVP 采用人工销售 |
| 微信深度接口 | P2 | 裁剪 | 自动发布等受限，MVP 仅做辅助生成(草稿/建议)+跳转链接（PRD-06 风险3 / D3） |
| 支付系统 | P2 | 裁剪 | MVP 线下成交/手动记录，支付非必需 |

## 5. MVP 验收标准细化（可勾选清单）

将 PRD-05 §10「产品验收」与「商业验收」拆解为可勾选条目，并补全主链路隐性要求。

> **验收边界声明（与 §0.5.1 一致）**：① NFC 真机写卡 / 读取**不列入** MVP 验收点（二维码为主路径）；② AI 内容（脚本/评论/活动/优化建议）仅验收"生成草稿 / 建议文本"，**不验收"自动发布到视频号"**；③ agent 角色仅验收"枚举与鉴权钩子预留"，不验收任何代理业务功能。

### 5.1 产品验收（功能项 + 验收口径）

| # | 验收功能项 | 验收口径（可勾选标准） | 对应模块/接口 |
|---|---|---|---|
| 1 | 管理员登录 | 使用账号密码可登录后台，错误凭证被拒，登录态可保持 | `POST /api/auth/login`、`sys_user` |
| 2 | 创建商家 | 后台可新增商家并落库，列表即时出现该商家 | `POST /api/merchant/create`、`merchant_info` |
| 3 | 商家信息管理 | 可编辑商家资料（含视频号链接）、可禁用、可软删除（不硬删） | `PUT /api/merchant/update` |
| 4 | 创建种草卡 | 填写名称/场景/跳转目标/绑定视频后可生成种草卡记录 | `POST /api/seed-card/create`、`seed_card` |
| 5 | 生成二维码 | 种草卡生成后可得二维码图片（segno），支持页面展示与下载 | `seed_card.qr_code`、二维码接口 |
| 6 | 用户访问记录 | 消费者扫码/点击 H5 落地页，scan/click 事件写入 `seed_event` | `POST /api/seed-card/event` |
| 7 | AI 生成评论 | 输入视频主题+行业，返回多条不重复、拟真语气评论（Mock 亦可） | `POST /api/ai/comment` |
| 8 | AI 生成内容（草稿） | 输入行业/活动，返回视频标题+脚本草稿（或活动文案草稿），由商家手动发布 | `POST /api/ai/content` 或 `/api/ai/report` |
| 9 | 基础数据统计 | 后台可查看种草卡生成数/扫码数/点击数/AI 生成次数 | `GET /api/stats/overview` |
| 10 | AI 商家诊断（P0 附加） | 输入商家信息可生成现状/机会/方案网页报告 | `POST /api/ai/report` |
| 11 | 跳转可用（主链路隐性） | H5 落地页"前往视频号/自定义链接"按钮可正确外跳（非自动发布） | `seed_card.target_url` |
| 12 | 消费者 H5 入口（主链路隐性） | `GET /api/seed-card/{id}` 可返回可访问的纯静态 H5 落地页 | 消费者入口 I |

### 5.2 商业验收（闭环验证）

| # | 验收项 | 验收口径 |
|---|---|---|
| B1 | 真实商家 ≥1 家 | 至少有 1 家真实签约/试用的实体商家被录入系统并完成种草卡部署 |
| B2 | 扫码→点击闭环 | 该商家种草卡被真实消费者扫码，且产生 scan 与 click 记录 |
| B3 | 互动闭环 | 消费者通过落地页跳转视频号并手动发布互动内容（评论或内容互动） |
| B4 | 数据可追溯 | 后台能查到该商家种草卡的生成/扫码/点击完整数据，证明闭环跑通 |

> 商业验收 B1–B4 为 PRD-05 §10「至少 1 家真实商家完成扫码→点击→互动闭环」的细化，是 MVP 是否"验证商家愿付费"的最终判据。**NFC 真机写卡/读取不纳入本验收。**

## 6. 给架构师的任务拆解提示（产品视角）

- **Sprint 顺序建议**（对齐 PRD-05/PRD-06）：Day1 用户系统 → Day2 商家管理 → Day3 种草卡+二维码(segno)+H5 落地页 → Day4 AI 评论+内容(草稿) → Day5 后台页面 → Day6 数据统计 → Day7 部署。
- **最大风险点**：消费者 H5 落地页（I）与扫码事件记录（seed_event）是主链路"最后一公里"，务必 Day3 即可真机测试，不要留到最后。
- **不要过度设计**：NFC、小程序、CRM、雷达、支付、代理一律不在 MVP 建表之外做扩展，仅 `sys_user.role` / `seed_card.type` 预留字段即可；`agent` 角色仅预留枚举与鉴权钩子，具体逻辑 V2 不实现（D4）。
- **AI 接口两条足矣**：`/api/ai/comment`（评论）+ `/api/ai/content`（脚本/文案/诊断报告可同源或区分），先接通 LLM（默认 Mock 兜底）再补结构化输出；所有 AI 输出仅作草稿/建议，不自动发布（D3）。
- **数据层**：默认 SQLite（`DATABASE_URL` 可切 PG），MVP 不引入 Redis；P0 在"SQLite + Mock"下离线无 Key 完整跑通（§0.5.3）。
