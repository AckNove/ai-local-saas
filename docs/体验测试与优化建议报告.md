## 二、WeChat-POI-Groupbuy-SaaS：修复的阻断性 Bug（4 个）

### 🔴 Bug 1：web-admin 前端 API 路径与后端路由错位（4 处 404）
**影响**：门店管理、套餐管理、预约管理、视频号挂载**四个核心页面全部无法加载数据**（打开即 404），商家上线流程在界面上完全走不通。

| 前端调用（错误） | 后端实际路由（正确） |
|---|---|
| `/stores` | `/tenants/stores` |
| `/packages` | `/catalog/packages` |
| `/reservations` | `/fulfillment/reservations` |
| `/video-bindings` | `/fulfillment/video-bindings` |

**修复**：`web-admin/src/api/stores.ts`、`packages.ts`、`dashboard.ts` 路径对齐后端路由前缀。

### 🔴 Bug 2：平台账号无法核销任何订单（verify_code 未豁免 platform）
**影响**：平台运营 admin 核销任意订单返回 `4002 无效核销码`（跨商户校验把 platform 也拦了）。
**修复**：`backend/app/services/verification.py` 跨商户校验加 `not ctx.is_platform` 豁免。
**验证**：admin 核销成功 → 重复核销 `4001` 幂等拦截 ✅

### 🔴 Bug 3：dev.db 表结构漂移（video_channel_binding 缺 poi_name 列）
**影响**：视频号挂载页打开即 500（ORM 查 `poi_name` 列，但表是旧 create_all 结构）。
**修复**：`ALTER TABLE video_channel_binding ADD COLUMN poi_name`（表为空，无数据风险）。
**验证**：`POST /fulfillment/video-bindings` 从 500 → 200 ✅

### 🔴 Bug 4：前端列表请求 page_size=200 超后端上限 100
**影响**：路径修复后，5 处 `page_size: 200` 请求触发后端 `422 参数校验失败`（`le=100`）。
**修复**：ChannelBinding / PackageManage / StaffManage / StoreManage 统一改 `page_size: 100`。

### 🟡 附带修复：视频号绑定列表返回类型错位
`GET /video-bindings` 返回 `{list,total,page,page_size}`，前端却声明 `VideoBinding[]` 直接 `setBindings(bs)` → 渲染崩溃。已改为 `bs.list`。

## 三、WeChat-POI-Groupbuy-SaaS：补齐的功能缺口（2 项）

### 🔴 缺口 1：前端没有「商户管理」页面（商家上线第一步断在界面）
后端有 `/tenants/merchants` API，但 web-admin **没有任何页面能创建商户**——平台运营只能在命令行 curl 建商户。
**补齐**：新增 `pages/MerchantManage.tsx`（商户列表/新增/编辑/停用/软删除），路由 `/merchants`，侧边栏"🏢 商户管理"（仅平台运营可见）。

### 🔴 缺口 2：前端没有「员工管理」页面
无法为门店分配核销员/店长账号。
**补齐**：新增 `pages/StaffManage.tsx`（员工列表/新增/编辑/删除，角色=店长/核销员，关联门店），路由 `/staff`，侧边栏"👥 员工管理"。

### 🟡 附带补齐：门店表单无「所属商户」下拉
平台创建门店时后端强制要求 `merchant_id`（否则 400），但前端表单没这个字段 → **平台无法在界面上创建门店**。
**补齐**：`StoreManage.tsx` 平台视角显示"所属商户"下拉（默认第一个商户）。

## 五、全流程测试结果（修复后）

### WeChat-POI：商家上线完整闭环（API 16/16 + UI 7/7 全通过）
```
平台登录 → 建商户 → 建门店(未配POI) → 配置地图POI(经纬度/POI ID) → 视频号挂载绑定
→ 创建2个套餐(含图片JSON) → 上架 → 消费者浏览已上架套餐 → 下单 → 支付回调
→ 生成核销码 → 平台核销成功 → 重复核销4001幂等拦截 → 订单状态 fulfilled
```
浏览器端实测：新建商户 → 新建门店+POI → 视频号绑定，**真实点击全部成功**。

### AI-Local：管理/商家/消费者三视角全通
- **管理者**：登录 → 数据概览 → 建商家 → 建种草卡 → 二维码下载 → AI 诊断 → AI 评论，全通

- **消费者**：H5 落地页（手机视口）→ 跳转按钮 → 分享 → 写评论 → 事件上报，全通

## 六、体验问题与优化建议（剩余，非阻断）

### WeChat-POI：流程顺畅度

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | **POI 配置靠手填 ID/经纬度** | 商家老板不知道自己的 POI ID 和坐标，配置门槛高 | 接腾讯地图 Web 服务 API：输入地址→搜索 POI→地图选点自动回填（`MAP_POI_PROVIDER=real` 时）；Mock 阶段提供"附近门店搜索"演示 |
| 2 | **套餐图片是 URL 输入**（已从 JSON 手填改进） | 仍需商家自备图片 URL，无本地上传 | 增加图片上传接口（multipart → 本地/OSS 存储 → 回填 URL），表单里直接上传 |
| 3 | **无商户/员工管理入口**（已补齐） | —— | 建议商户详情页聚合展示"该商户的门店/员工/套餐"（目前三者分离） |
| 4 | 订单/套餐列表无筛选搜索 | 门店多了难找 | 增加关键词搜索、状态筛选、分页 |
| 5 | 核销员只能核销本店订单 | 连锁门店核销员不能跨店支援 | 可加"跨店核销"开关（平台配置） |
| 6 | 数据看板无日期范围筛选 | 无法看周报/月报趋势 | 增加 date_from/date_to 筛选 + 趋势折线 |

### AI-Local：三视角不合理设计

**管理者维度**
| # | 问题 | 建议 |
|---|---|---|
| 1 | 商家列表无"门店数"详情入口，商家详情与门店管理分离 | 商家卡片直接展示门店列表/种草卡数 |
| 2 | 无套餐到期提醒（expire_time 字段有但不告警） | 概览页加"即将到期商家"提醒 |
| 3 | 数据概览无趋势（只有累计值） | 加时间维度折线（扫码/点击按天） |

**商家维度**
| # | 问题 | 建议 |
|---|---|---|
| 1 | 商家没有"我的资料/我的门店"页（菜单无入口） | 增加"我的门店"页：查看/编辑自己门店、视频号账号 |
| 2 | 商家看不到自己的种草卡数据明细（只能看卡片列表） | 商家 Dashboard 加"我的种草卡效果"（扫码/点击趋势） |
| 3 | 商家无法自助申请新种草卡物料 | 可加"申请物料"流程（提交→管理员确认） |

**消费者维度**
| # | 问题 | 建议 |
|---|---|---|
| 1 | H5 落地页无商家信息展示（只有卡片名+按钮） | 展示商家名/门店地址/电话，增加信任感 |
| 2 | 落地页无"附近门店/更多优惠"入口 | 增加商家主页入口（POI 链接） |
| 3 | 评论区无历史评论展示 | 落地页展示精选评论（来自 seed_event.comment） |
| 4 | 无分享到朋友圈的引导 | 分享按钮增加复制文案/海报生成 |
